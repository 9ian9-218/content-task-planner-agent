# 项目 PRD：内容任务规划 Agent

版本：v0.3；日期：2026-10-28（Asia/Shanghai）；题号：2。本文保留产品规格；核心功能及 P1 续跑已实现并完成离线验证，真实模型效果待配置。实际结果见 [03-evaluation.md](03-evaluation.md)。需求依据为用户提供的考核题面；调研依据见 [00-competitive-research.md](00-competitive-research.md)。

## 1. 产品目标与用户

为内容运营人员生成一份在预算和截止时间内可完成、可编辑、可检查的内容活动方案。当报价超限、资料不足或工具失败时，Agent 应调整行动或说明未完成原因，并保留已经成功的工作。

主要用户是需要快速形成内容方案的运营人员；评审人员需要通过运行命令、测试和实际 Trace 判断结果是否可信。首个场景限定为“一次主题内容活动的一份方案与一份短视频脚本草稿”，不扩展为完整营销平台。

交付价值：减少人工来回核对素材、费用和执行状态的工作，并让使用者知道哪些结果已经生成、哪些仍然缺失。本文不承诺效率提升比例，也不把可运行原型等同于生产系统。

## 2. 范围与产品取舍

### P0：提交所必需

- CLI 读取结构化活动需求；检查主题、预算和截止时间。
- 提供素材检索、脚本生成、成本及时间估算、方案保存四类工具。
- 真实模型根据工具结果自主选择后续工具、替代方案、请求补充或结束；允许保留步骤依赖骨架。
- 预算、时间、素材编号、步骤依赖和保存前提由程序校验。
- 失败后保留成功结果，准确展示每步状态和费用。
- 持久化请求与结果，重复执行不重复保存已完成方案。
- 设置执行上限，输出可核对的步骤记录。
- 提供离线 Mock 入口、可执行测试和实际示例记录；真实模型证据单独标注。
- 按考核规范交付 README、代码、测试、合成数据、examples 和五份指定文档。

### P1：P0 全部通过后再做

- 通过显式 `--resume` 从失败步骤继续执行，跨进程复用有效成功结果。
- 同一组真实模型场景重复运行，报告稳定性和一次有依据的提示词或工具描述改进。

### 本期不纳入

Web 界面、线上部署、多 Agent、外部发布、真实付费业务操作、完整生产调度、团队权限、向量数据库、多个模型供应商适配。脚本时长与品牌审查不作为本题新增验收范围。

## 3. 关键业务定义

术语详见 [CONTEXT.md](../CONTEXT.md)。以下是本项目对题面歧义作出的明确约定，可在开发前按用户意见调整：

1. **“完成”指满足约束的活动方案已生成并保存。** 不代表活动已经执行、视频已经制作或内容已经发布。
2. **预算使用整数模拟单位。** 合成费用表中定义业务工具的费用；真实模型 API 费用单独记录用量，不算入该模拟预算。预算为 0 合法，但当前收费方案可能无法完成。
3. **方案预计费用 = 已发生费用 + 剩余预计费用。** 候选方案估算不收费；只执行一个候选方案时，不把所有互斥候选报价相加。已完成收费步骤即使后来不再采用，其费用仍保留。
4. **截止时间约束方案生成与保存流程。** 采用合成工具耗时表模拟业务进度，不对实际视频制作排期作承诺。
5. **“保留成功结果”是 P0，“重启后继续失败步骤”是 P1。** P0 在同一次运行中允许模型复用结果、重试或选替代工具；重复提交未完成请求时先返回已保存的状态快照，不默认从头重做。
6. 缺少硬约束时不猜测。模型无权增加预算、延后截止时间或把失败结果标为成功；需要改变要求时明确请求用户补充，以新需求标识再次提交。

### 3.1 合成工具费用与耗时

默认提供两个脚本档位。它们都是本地业务工具的模拟能力，描述差异用于模型选择，不代表对真实文案质量的测量。

| 操作 | 模拟费用 | 成功业务耗时 | 说明 |
| --- | ---: | ---: | --- |
| 素材检索 | 0 | 1 分钟 | 返回素材事实、来源与可选档位；最终报价以估算工具返回为准 |
| 成本及时间估算 | 0 | 1 分钟 | 给出候选方案费用、剩余耗时、缺口和是否可行 |
| standard 脚本生成 | 场景配置为 8 或 12 | 40 分钟 | 较完整的内容结构；报价可因模拟供应条件不同而变化 |
| economy 脚本生成 | 8 | 20 分钟 | 精简结构，满足核心交付要求 |
| 方案保存 | 0 | 1 分钟 | 成功后生成唯一方案记录 |

失败口径：本地故障注入发生于事务提交前，模拟费用为 0、业务耗时为 1 分钟；该规则写入数据表。被程序拦截的非法动作不计模拟费用与业务时间，但计入执行上限。复用已成功操作不重复计费、不重复累加业务耗时。

所有收费和副作用工具均为本地可确定事务结果的模拟实现。本期不处理真实远端工具“已经扣款但响应丢失”的不确定结果；后续接入此类工具必须增加对账机制。

### 3.2 时间口径

- 接受带时区的 ISO 8601 截止时间；展示默认使用 Asia/Shanghai。无时区时间应请求补充。
- 运行起点为启动时的业务时间；演示和测试可通过显式 `--as-of` 固定起点，并在结果中展示。
- 业务当前时间 = 起点 + 已发生操作的合成耗时。再次估算、失败尝试都会推进时间，不因为改方案而清零。
- 预计完成时间 = 业务当前时间 + 当前方案尚未执行的步骤耗时，必须包含保存步骤。
- 预计完成时间等于截止时间时允许完成；超过则阻断收费操作和保存。
- 真实运行时间、模型网络超时独立统计，不能将合成耗时当成实测性能。

## 4. 输入与输出

### 4.1 输入契约

| 字段 | 要求 | 缺失或无效时的行为 |
| --- | --- | --- |
| `topic` | 必填，去除首尾空白后非空，最长 200 字符 | 缺失返回 `needs_input`；类型错误返回 `invalid_request` |
| `budget_units` | 必填，非负整数，布尔值不作为整数接受 | 缺失返回 `needs_input`；负数、非整数返回 `invalid_request` |
| `deadline` | 必填，带时区的 ISO 8601 时间 | 缺失或未提供时区返回 `needs_input`；无效日期返回 `invalid_request` |
| `request_id` | 可选；有值时为非空标识 | 未提供则由规范化业务输入生成稳定标识；同标识不同需求返回冲突 |
| `preference` | 可选，`quality_first` / `cost_first`，默认前者 | 是软偏好，必须服从预算和截止时间 |

测试场景、故障注入和业务起点由运行配置提供，不是模型可修改的业务输入。缺失必填项时仅展示待补充字段，不调用业务工具；输入字段规范化只处理空白、枚举和时间等价形式，不改写用户意图。

以下仅为**规格示例输入**，不是已经运行的案例：

```json
{
  "request_id": "demo-001",
  "topic": "面向新手介绍合成产品 P01 的字幕功能",
  "budget_units": 10,
  "deadline": "2026-11-01T11:00:00+08:00",
  "preference": "quality_first"
}
```

### 4.2 输出契约

输出 JSON，并可导出一份便于阅读的 Markdown 方案。至少包含：

- 请求标识、任务状态、模式、资料和费用表版本、真实及业务起止时间。
- 活动目标、内容提纲、素材来源 ID、脚本草稿、执行步骤与依赖。
- 各步骤及各次尝试的状态、工具结果引用、错误码；未执行的建议任务标注为 `pending`。
- `spent_units`、`remaining_units`、`projected_total_units`、预算上限、预计完成时间及缺口。
- 保存状态 `not_attempted` / `saved` / `failed`，以及仅成功时存在的 `plan_id`。
- 待补充字段、未完成原因、可复用结果、Trace 路径。

状态定义：`completed`（所有硬约束成立且已保存）、`needs_input`（缺必要输入或资料）、`incomplete`（当前未能完成）、`invalid_request`（格式或请求标识冲突）。`running` 仅用于过程记录。步骤使用 `pending` / `running` / `succeeded` / `failed` / `skipped`；不再选用的成功结果保留 `succeeded` 并额外标注 `selected=false`。

CLI 退出码建议：0 为 `completed`；2 为 `needs_input` 或 `invalid_request`；3 为 `incomplete`。业务失败也必须输出结构化结果，不只抛出异常文本。

## 5. 功能需求与验收

| 编号 | 优先级 | 需求与验收条件 |
| --- | --- | --- |
| FR-01 | P0 | 检查主题、预算、截止时间，分别覆盖缺预算与缺截止时间；缺失时指出字段且不产生收费调用。 |
| FR-02 | P0 | 提供四类工具，参数与返回值结构化；素材、档位和引用必须实际存在。 |
| FR-03 | P0 | 真实模型至少完成一次“选择工具→执行→观察→决定下一步”循环；超限后的替代方案由模型选择，不能由固定分支替代。 |
| FR-04 | P0 | 模型观察到超预算或超时后可选择低成本/更快方案、补查或停止；任何成功方案都要重新核算。 |
| FR-05 | P0 | 正常路径返回活动方案、成功步骤、脚本、成本与已保存方案标识；只有本地保存事务明确成功才能输出 `completed`。 |
| FR-06 | P0 | 工具失败返回错误码与实际计费/耗时，原有成功结果仍可检查；允许模型选择重试、替代或未完成。 |
| FR-07 | P0 | 同标识同需求再次执行，返回原结果，不新增方案、不重复模拟收费；同标识不同需求返回 `REQUEST_ID_CONFLICT`。 |
| FR-08 | P0 | 默认最多 12 次模型决策、12 次工具动作尝试；非法与被拒动作也计数。次数用尽且尚未保存时返回 `incomplete`。180 秒为停止派发阈值，禁止启动后续动作；不强制抢占已在提交的本地事务。若该事务已保存但耗时超限，保留真实回执并标记 `runtime_limit_exceeded`。 |
| FR-09 | P0 | Trace 记录步骤、动作来源、工具参数、结果摘要、后续动作和简短依据；后续动作必须来自实际下一次决策记录。 |
| FR-10 | P0 | 明确区分 `live` 与 `mock`。模型不可用返回未完成，不在 live 模式中静默切换为 Mock。 |
| FR-11 | P0 | 保存前重新核验预算、时间、输入指纹、素材、生成结果和候选方案的一致性，模型的自然语言声明不能跳过检查。 |
| FR-12 | P1 | 显式续跑只执行需要补做的步骤；有效成功结果、已发生费用和耗时在重启后仍保留。 |

单次网络等待超时不超过 30 秒，并受派发期限剩余值约束；默认不做隐藏的模型网络重试。多工具调用按模型返回顺序串行校验，逐项计数；先前结果使后续调用前提变化时，应拒绝该调用并把结果交回模型。

## 6. 正常与异常用户旅程

1. 用户提交需求，程序校验并识别是否重复。
2. 模型检索素材，选择候选档位并调用估算工具。
3. 报价/时间满足要求时，模型选择生成脚本；收费动作前再次校验。
4. 超限时，模型依据返回的缺口选择调整或停止；脚本失败时保留先前检索结果。
5. 脚本成功后，模型选择保存；保存失败时保留脚本，不得把“有脚本”描述成“已保存”。
6. 程序根据工具事实生成最终结果；同请求再次执行返回已有结果。

这是一种允许的流程骨架，不预设每条路径的工具顺序、替代方案与成功结局。模型也可能直接选择可行的 economy 方案；该次记录必须如实呈现，不能加工成“先失败再重规划”。

## 7. 代表性场景与预期

以下均为待验证的场景设计，详细矩阵见 [03-evaluation.md](03-evaluation.md)。业务起点统一为 `2026-11-01T10:00:00+08:00`。

| 场景 | 条件 | 预期 |
| --- | --- | --- |
| 正常完成 | 预算 10、截止 11:00，standard 实际报价 8 | 若采用 standard，费用 8，成功保存；预计时间包含检索、估算、生成、保存 |
| 信息不足 | 缺预算或截止时间 | 返回 `needs_input`，不调用收费工具、不保存 |
| 预算重规划 | standard 报价 12、economy 报价 8、预算 10 | 若模型先询价 standard，观察超限后可转 economy，重新估算并保存 |
| 无可行方案 | 两个档位均高于预算 5 | 返回 `incomplete`，说明已检查方案的费用缺口，不执行收费操作 |
| 时间不足 | 截止 10:10，最短生成需 20 分钟 | 返回未完成和时间缺口，不擅自修改截止时间 |
| 保存失败 | 脚本成功、保存持续失败 | 返回 `incomplete`，保存错误包含 `SAVE_FAILED`；若达到执行上限则明确主终止原因。保留脚本、费用和失败尝试，无成功保存标识 |
| 重复执行 | 同一请求执行两次 | 同一结果/方案标识，方案数量仍为 1，模拟费用不增加 |

## 8. 成功标准与评审证据

- **验收覆盖**：题目五类必须验收全部有可执行测试；正常、信息不足、工具失败至少各有一组实际输入/输出/Trace。额外保存超预算路径，使动态决策易于核对。
- **硬约束可靠性**：离线测试中不存在超预算完成、超时完成、假保存成功、重复保存、失败步骤标成功。当前 63 个测试通过、18 组案例符合预期；范围与局限见实际评估报告。
- **真实决策证据**：至少两条不同的真实模型路径，能够看到模型在不同工具返回后做出不同动作。业务工具可以是合成 Mock；决策来源必须标为真实模型。
- **可复制运行**：新环境按 README 安装、执行 Mock 与测试；有合法模型凭据时可运行 live。版本与模型标识在实现阶段记录，不声称不同模型版本能逐字复现。
- **诚实交付**：不手写“实际输出”，不隐藏失败样本；个人修改、AI 使用范围、实际耗时与未完成部分据实填写。

## 9. 风险、限制与待决项

| 项目 | 当前处理 |
| --- | --- |
| 缺少真实模型凭据或网络不可用 | 当前规划阶段不需密钥；开发第一步验证 live 调用。若不可用，保留 Mock 交付并明确真实决策证据未完成。 |
| 模型提前选中便宜方案，未出现重规划 | 如实保留；使用质量优先软偏好及只有估算工具可知的最终报价构造对照场景，不伪造动作。 |
| 截止时间口径与真实生产场景不同 | 本期采用显式合成业务时钟；后续真实接入重新定义外部操作耗时。 |
| 三小时内时间不足 | 保留全部 P0 验收，舍弃 P1、界面和额外集成；如 P0 仍未完成，如实记录缺项。 |
| 账号与模型选择 | 用户已授权网关 `http://100.73.185.103:8045/v1`；原指定写法为 `claude-opus-4.6`，当前使用网关公开且已实测的同系列 ID `claude-opus-4-6-thinking`。认证、原生工具调用和实际重规划已验证，见模型接入与评估报告。 |
| 本地并发范围 | 支持单机串行运行和唯一约束防重复保存；同请求并发执行时拒绝正在处理的重复请求，不承诺分布式执行。 |

本 PRD 的“预算是模拟工具费用”“截止时间是方案完成时间”属于明确的 MVP 假设，已经在输入、输出和测试中保持同一口径；若后续改为真实活动采购预算与生产截止时间，应同步修改费用模型、时钟、工具及验收用例。
